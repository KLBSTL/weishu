# 双人首领战部署费用显示修复

状态：用户已要求将两人的部署费用分开，并只做必要测试后与本次软禁修复一起发布。草案先于代码写入；现已实现并完成以下必要验证。

## 已核验的原因

- `Battle._addPlayer` 为每名玩家创建独立 `dp`；自然回复逐玩家处理，先锋回费与再部署扣费均通过单位的 `ownerId` 找到账户。
- 多人快照已携带 `dps: { [playerId]: number }`，但界面的 `snapHud` 丢弃了它，只读兼容字段 `dp`，该字段取同场第一名玩家的费用。因此双人最终攻势/隐秘核心的两端显示了同一人的余额。
- 不需要另加资金池或改变首领血量共享规则；本次修复费用显示，并用真实战斗回归确认两人的回复与扣费确实独立。

## 实施口径

- HUD 保留多人快照的逐玩家费用，以当前查看的玩家为准；采用现有盟约栏的玩家选择规则，避免镜头与费用错位。
- 全景显示参战者自己的余额；左/右半场显示该半场玩家的余额；观战跟随查看对象。切换半场时即刻重算，无需等下一帧。
- 单人及不含 `dps` 的兼容快照继续使用 `dp`。含多人费用表但缺少目标玩家时不显示其他人的余额。
- 再部署、技能回费、商人扣费的引擎规则与初始10/+1每秒/上限99不变。

## 必要验收计划

1. 真实双人最终攻势与隐秘核心：回费、自然回复、余额不足、自动再部署和主动付费再部署只影响所属玩家；快照携带不同余额。
2. HUD 数值与玩家/半场选择回归：双方全景、左右切换、观战、缺失玩家与单人兼容。
3. 相关静态检查与文档检查；这是显示修复，战斗结果不应改变，不为本修复重建 golden 或进行 AI 胜率测试。
