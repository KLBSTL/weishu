# 原版表现复刻与上游迁移草案

日期：2026-10-15。状态：**本轮确定的A→B→C→D迁移已完成并通过本地验收，未提交、未上传GitHub。AI优化保持暂停，保留已有本地代码、草案与测试结果。** 原调研记录保留，实施结果与验证见第10、11节。

## 1. 目标与建议顺序

用户希望恢复原版的碰撞/偏移表现、地图贴图及各类视觉效果，并利用上游已有更新。本轮先确定可迁移内容、素材来源、兼容边界和验收方法。

建议分批实施：**官方地图与素材加载 → 模型对齐与动画修复 → 战斗/环境特效 → 单独处理会改变战斗结果的受击格判定。** 不整体合并上游版本，也不把尚未合入的PR当作已完成的功能。

“碰撞偏移”目前没有对应的指定录屏片段，草案先拆成拖拽落格、模型显示偏移、推拉滑行、受击判定和群体挤压五类。它们的坐标来源及影响不同，不能统一给模型加一个偏移值。

原调研轮没有修改玩法、AI、素材、依赖、生成数据、语言包或渲染代码；没有下载完整素材包、启动游戏、进行截图对照或推送远端。后续授权实施的进度见第10节。

## 3. 碰撞、位移与模型偏移

### 3.1 拖拽与落格：先验收现有行为

上游PR #403曾建议改变拖拽选格偏移，但没有合并。维护者对照实机后保留“指针所在格为落点”，改成拖到合法格时模型直接站到该格；维护者说明该处理已在0.2.2发布。本地app.js中也已存在dragStandTile → boardWorld这一处理。**不能重新套用已被放弃的pickDragTile补偿，再产生一格误差。** [PR及维护者说明](https://github.com/sganggs/Stronghold-Protocol/pull/403#issuecomment-6067565897)。

拟检查：鼠标/触摸、普通格/高台/水上平台、备战区、Boss准备区、不同相机角度和DPR下，落点高亮、模型脚底、阴影、松手后的实际部署格是否一致。先复现具体错位，再定位相机反投影、高度或准备区变换；不改合法部署规则。

### 3.2 模型显示偏移：脚底、血条、裁切分别修

- 使用单位世界坐标与地形高度定位脚底；Graphic相对变换、模型横纵缩放、飞行高度及动画骨骼位移各保留其语义。现有enemyModelScale/modelScaleY不能被统一缩放替换。
- 本地enemy_model_offsets.py已区分prefab根节点的编辑器遗留位置与Graphic子节点的真实相对变换。不要把根节点localPosition搬成战斗坐标偏移，也不要因素材悬垂而统一抬高所有模型。
- 迁入上游血条高度修复：按模型基点以上的有效高度定位，避免含脚下延伸的大包围盒把血条顶远。具体依赖以units.js的最终差异为准。
- 迁入0.2.6的完整impostor修复链：以idle为核心测量动画边界，每个缓存槽独立裁切，超出上限或无法测量的动画直接绘制；冻结模型先落到动画首帧。修复旗帜/枪械被裁掉、模型错位和残留像素。
- 同时处理队列生命周期、销毁清理及批处理缓冲，不只取最早一个裁切提交。上游最终阈值是循环动画5倍、单次动画2倍核心边界；这些是上游实现参数，不代表已在本分支验收。

涉及public/js/render/units.js、spine.js、impostor.js及app.js。units.js、spine.js含本地修改，必须逐函数迁移，保留额外皮肤及正面/背面/基建动作选择。缓存键需区分实际皮肤模型、朝向和动画集，防止不同皮肤共用错误边界。[上游模型裁切设计及假设](https://github.com/sganggs/Stronghold-Protocol/blob/488db49f11daf862b67ce26fa4cf89aa6cba2466/docs/history/0.2.6.md)。

### 3.3 推拉滑行：保留动作朝向

上游已增加keepFacing：推/拉事件默认保持受击前朝向，滑行时不再根据横向速度突然翻面。原始位移仍可选择不标记。拟迁入事件字段、客户端slide消费和相应测试，不重新设计冲量、摩擦、重量、阻挡或位移距离。

上游对野鬃/莫斯提马推及歌蕾蒂娅部分拉有实机依据，其他来源沿用仍标为[ASSUMED]。新增特效字段可能影响事件序列或golden散列；必须核对，不能因“纯显示目的”直接跳过模拟回归。[对应提交](https://github.com/sganggs/Stronghold-Protocol/commit/4980ee786f6d79dfc235f85fa9f9f7dc3e4ce933)。

### 3.4 受击格与场地边缘：会改变玩法，单独迁移

上游PR #520已合入；本地body.js仍使用Math.round。差异是精确半格处按四舍六入五成双取格，例如10.5归第10格，11.5归第12格；同时把场地边缘夹取到内侧极小距离，避免敌人实际被判到场外格。

拟完整检查detmath.js、body.js、battle/queries.js、targeting.js、constants.js、battle/spawns.js及相关用例。**不能只改body.js，留下查询索引和目标选择口径不一致。** 原PR未将该规则推广到移动通行、推开、阻挡或客户端选格；本分支也不全局替换Math.round。

这会改变部分范围选敌与事件顺序，列为独立规则修复提交。先在当前扩展版本重算影响，再逐场解释golden差异；不得直接复制上游golden。上游PR自述的通过结果和变化场景仅作线索，不作为本地验证结果。[PR #520的依据、改动与边界](https://github.com/sganggs/Stronghold-Protocol/pull/520)。

### 3.5 群体碰撞/挤压：尚未确认可直接迁入

本次核查master的body.js、ai.js及battle/displacement.js，未找到新增的通用群体避让或刚体碰撞系统；已有体积、射程接近和推拉不等于单位相互挤开。

若用户指的是密集敌人重叠时的侧移/挤压，需要后续实机片段明确：是否改变路径、阻挡和射程，还是仅模型/阴影错开。[待验证] 在证据明确前，不新增会改变正式战斗的随机排斥力或“物理引擎”。开发对照可显示逻辑中心、hitArea、模型基点与阴影位置，但调试标记只放开发视图。

## 4. 官方地图与素材方案

### 4.1 复用上游场景，而非给平面棋盘换一张图

上游按每个战场加载预制场景的网格、材质、贴图、烘焙光照和分组，不是运行时仅拼不同颜色的金属地砖。11个战场分别使用沙地、叙拉古和卡西米尔相关主题；场景包含普通战斗两侧与Boss区的分组。[场景提取与坐标设计](https://github.com/sganggs/Stronghold-Protocol/blob/488db49f11daf862b67ce26fa4cf89aa6cba2466/docs/history/0.2.5.md)。

拟迁入：

1. tools/local-extract/scenes.py、fetch_scenes.py，以及extract.py的场景导出与BC5/DXT5nm法线解码部分。
2. board3d/load.js的场景解析、分组、缓存与失败重试；scene.js/materials.js的网格、材质、光照和场景切换。
3. app.js按stageId异步加载场景；快速换图/退出时校验当前stage和生命周期，避免旧请求覆盖新地图。
4. 同材质/光照页网格合并，减少绘制调用；场景切换与WebGL上下文恢复正确释放和重建资源。
5. 0.2.6光照修正：使用导出光照语义，直射/间接增益各1，不保留0.2.5手调0.8/0.4，也不顺带迁入被上游放弃的金属板自发光改法。
6. 装置平台补绘：射击台、特制水上平台、封印地面仍可见并有正确侧面；普通高台由官方场景提供，不重复生成。阴影、地形说明、部署高亮和范围覆盖仍与逻辑格一致。

**启动依赖必须一并处理。** 当前boardArtListed/loadBoardPack仍要求基础棋盘atlas与map/fx等资源；只有11份scene.json/scene.bin也不一定能启动3D层。素材验收必须包含基础棋盘、门与装置、主题贴图、场景网格及光照的完整引用闭包。

3D网格仅决定表现，地图地块、通行、部署、阻挡、推拉边界继续来自游戏数据；不能根据装饰网格重建碰撞。中继试验场等本地自定义地图没有相应官方场景，继续用程序棋盘；不拿另一张官方图硬套其地形。

备用方案[已存在上游工具，未在本机执行]：从本地官方客户端取得基础地图/主题材质，使用fetch_scenes.py下载在季版本26-04-13-12-31-42_e9b560的场景包，再提取。上游清单记载33个包、压缩22,801,308字节，逐包校验MD5；该数字不是最终导出大小，也不包含本地主题素材。不能承诺“下载约23MB就有全部原版美术”。Python/UnityPy/lz4/Pillow仅是维护时提取依赖，玩家正常运行不应依赖它们。[素材依赖](https://github.com/sganggs/Stronghold-Protocol/blob/488db49f11daf862b67ce26fa4cf89aa6cba2466/docs/ASSETS.md)。

本分支既有规则是clone后可运行，同时不提交可选本地客户端提取目录。拟把审核过的场景和必要基础素材提升到可分发资源包，例如public/assets/scenes/，由构建脚本登记到主素材清单，并为现有localUrl接口增加兼容解析。目录及清单字段属于建议，实施前先用一张图验证最小适配。

- 不把整个public/assets/local/和机器专用data/local-assets.json强制加入版本库；继续保留可选本机覆盖入口。
- data/*.json由构建工具生成，不手改；记录资源路径、来源版本、哈希、字节数和依赖，检查重复与缺失引用。

- 保留GPL、NOTICE及官方素材权利归属和非商业说明；官方美术不能当作GPL代码素材重新声明。
- 回退顺序：匹配stageId的官方场景 → 已可用的程序3D棋盘 → 2D棋盘。缺文件不白屏、不循环加载；避免从未列入清单的地址猜测资源。
- 后续发布先在隔离目录检查clone启动及素材HTTP引用，再上传weishu；本轮不执行发布。
